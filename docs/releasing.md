# Publish a release
## Validate before tagging
Run `goreleaser check` and `goreleaser release --snapshot --clean`. Validate the installer under `debian:13-slim` and `busybox:1.37` with the commands in [AGENTS.md](../AGENTS.md#deploy). Before the first public release, complete the history audit and visibility checks in [Publication and rollout gates](deployment.md#publication-and-rollout-gates).

## Publish the tag
Choose an unused `v`-prefixed version. For example, to publish `v0.2.0`, run:

```sh
git tag v0.2.0
git push origin v0.2.0
```

The release notes are generated by [GoReleaser](https://goreleaser.com) from the commits since the previous tag, grouped by conventional-commit type (`feat`/`fix`, with an "Other changes" bucket) and with merge commits and `chore(deps)`/`ci`/`style`/`test` noise excluded. See [`.goreleaser.yml`](../.goreleaser.yml) for the exact filters.

The release ships two archives (`azath_linux_amd64.tar.gz`, `azath_linux_arm64.tar.gz`), `checksums.txt`, and the root-run `install.sh` as release assets. The workflow asserts exactly those assets are published.

## Verify and roll out
After the [Release workflow](../.github/workflows/release.yml) succeeds, verify unauthenticated asset downloads and smoke-test Debian 13 and DSM 7. Follow [Publication and rollout gates](deployment.md#publication-and-rollout-gates) before upgrading redundant servers.
